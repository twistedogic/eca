Caching

System Design Interview · 6 min read

A cache stores copies of data in a fast layer close to where it is requested, so future requests are served quicker. When a request can be served from the cache without hitting the origin, it is called a cache hit; otherwise it is a cache miss.

Key terms in bold become quiz questions automatically. This sentence's bold terms will show up in the chapter quiz with distractors pulled from sibling terms.

Common strategies include cache-aside, where the application checks the cache first and loads from the database on a miss, and write-through, where writes update both layers at once.

Eviction policy decides what the cache forgets when it is full — LRU (least recently used) is the usual default.
